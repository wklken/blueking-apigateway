### 2.2 命名约定

| 元素 | 规则 | 示例 |
|------|------|------|
| 资源名 | 名词复数 | `users`, `orders` |
| 操作 | 动词 + 资源 | `CreateUser`, `ListOrders` |

| 响应体 | 操作 + Response | `CreateUserResponse` |
| 字段 | snake_case（跨语言兼容） | `user_id`, `created_at` |

### 2.3 URL 设计规则

| 规则 | 说明 | 示例 |
|------|------|------|
| 资源用名词复数 | RESTful 风格 | `/api/v1/users` |
| 层级不超过 3 层 | 保持简洁 | `/api/v1/groups/{id}/members` |
| 版本号在路径中 | 方便迁移 | `/api/v1/`, `/api/v2/` |
| 自定义操作用动词 | 非 CRUD 操作 | `/api/v1/users/{id}:activate` |

## 三、数据类型映射

### 3.1 通用类型映射原则

- 整数类型超过 JavaScript 安全范围时，序列化为字符串
- 时间类型统一使用 ISO 8601 / RFC 3339 格式
- 枚举类型推荐使用字符串表示，避免数值歧义
- 空集合序列化为空数组 `[]`，不使用 `null`

### 3.2 常见陷阱

| 陷阱 | 原因 | 解决方案 |
|------|------|---------|
| 大整数精度丢失 | JSON number 精度有限 | 序列化为 string，前端 coerce |
| 空值语义不明 | null / undefined / 空字符串 混用 | 明确约定各类型的空值表示 |
| 时区问题 | 服务端/客户端时区不同 | 统一使用 UTC，展示时转换 |

## 五、前端接入规范

### 5.1 三层架构

| 层级 | 职责 | 修改规则 |
|------|------|---------|
| Generated / SDK 层 | 接口定义的客户端镜像 | 禁止手改 |
| Bridge 层 | 封装调用、类型转换、缓存 | 可修改 |
| Types 层 | 类型重导出 + 语义化别名 | 可修改 |

### 5.2 Bridge 层职责

- 调用 Generated/SDK 层的函数
- snake_case → camelCase 转换
- 大整数 coerce（string → number）
- 空值兜底（`?? []`、`?? ''`）
- 错误处理与重试逻辑

### 5.3 命名约定

| 操作 | 函数名 | HTTP 方法 |
|------|--------|----------|
| 列表查询 | `list{Resource}s` | GET |
| 单个查询 | `get{Resource}` | GET |
| 创建 | `create{Resource}` | POST |
| 更新 | `update{Resource}` | PUT |
| 删除 | `delete{Resource}` | DELETE |
| 自定义操作 | `{action}{Resource}` | POST |

## 六、核心契约模式

### 6.1 状态归一化

- 后端精细状态 → 前端展示状态（映射表集中维护）
- 展示用归一化状态（颜色、图标）
- 操作判断用原始状态（按钮禁用/可用）

### 6.2 扩展配置字段

- 使用 JSON 字符串字段扩展固定 Schema 的能力不足
- 必须包含 `version` 字段用于兼容性判断
- 解析必须 `try/catch`，提供默认值兜底

### 6.3 权限控制

- 权限判断封装为独立函数/Hook，统一复用
- 禁止在每个页面重复写权限逻辑

### 6.4 数据刷新策略

- 操作成功后立即刷新一次（不等轮询）
- 页面不可见时停止轮询，可见时恢复
- 上下文切换时重新触发加载

## 十、接口变更管理

### 10.1 兼容性规则

| 规则 | 说明 |
|------|------|
| 禁止删除已发布字段 | 标记废弃代替删除 |
| 新字段可选 | 新增字段必须向后兼容 |
| 版本升级 | 破坏性变更通过新版本路径 |

### 10.2 废弃流程

1. 标记 `@deprecated`
2. 提供替代方案文档
3. 保留至少一个版本周期
4. 全局搜索确认无引用后删除
