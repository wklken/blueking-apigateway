# 熵管理（Entropy Management）

> 目标：让文档、架构和代码随变更同步收敛，避免过时规则与无关改动累积。

## 1. 文档园艺

| 检测项 | 触发时机 | 处理 |
|-------|---------|------|
| Markdown 路径和相对链接 | 文档 PR | 阻断明显失效引用 |
| 根/组件 `AGENTS.md` 与目录、命令一致性 | 组件结构或工具链变化 | 同 PR 更新 |
| `docs/standards/` 与 Harness 预设一致性 | Harness 巡检 | 以预设覆写漂移 |
| 工作流模板一致性 | Harness 生成/巡检 | 未冻结时同步模板 |
| Dev Map 与代码结构一致性 | graphify 可用后 | 增量更新图谱 |

当前仓库未发现统一的自动文档巡检 CI。上述检查先作为 PR 验证合同执行；自动化接入方式待确认。

## 2. 漂移分级

| 级别 | 示例 | 行为 |
|------|------|------|
| P0 | 路径失效、命令错误、预设文件漂移 | 可验证后直接修复 |
| P1 | 架构描述与实现冲突、职责边界变化 | 给出证据和方案，人工确认后修复 |
| P2 | 表述、示例或可读性改进 | 仅在任务范围内处理 |

不要把 P2 清理混入功能或修复 PR；每一行变化都应能追溯到当前任务。

## 3. 技术债管理

| 债务类型 | 识别方式 | 处理原则 |
|---------|---------|---------|
| 反向/循环依赖 | import-linter、Go/Python/TS 静态检查 | 合入前修复 |
| 死代码和代理层 | 符号搜索、覆盖率、refactor audit | 重构后逐符号确认 |
| 过时接口或字段 | API 一致性检查、全局引用搜索 | 保留兼容期并记录迁移 |
| 过时文档 | Harness 巡检、路径检查 | 简单项直接修复 |
| TODO/FIXME | 代码搜索和 Issue | 不在无关 PR 顺手清理 |

仓库不设未经团队确认的固定债务数量目标。优先级按安全/兼容性、架构边界、交付阻塞、维护成本排序。

## 4. 变更卫生

- 功能和修复 PR 保持单一目的，不重排无关 import 或格式。
- 重构后列出移动、重命名、提取和删除的符号，并搜索生产代码与测试调用点。
- 仅测试调用的生产符号视为可疑：删除，或记录明确兼容性理由。
- 删除代理方法、死代码、无用 import、fixture 和只覆盖已删除代理的测试。
- 保留仍有价值的注释和领域约束，不因重写而丢失上下文。

## 5. 度量

初始关注以下可验证信号，不建立虚假看板：

- 文档引用检查通过率
- PR 中无关文件/行数量
- 新增架构违规数
- 验证失败与重复修复次数
- Harness 巡检发现的 P0/P1 数量

采集频率、负责人和目标阈值待团队在实际运行后确定。

## 检查清单

- [ ] 文档和代码变更保持同 PR 同步
- [ ] 没有无关清理、格式化或范围扩张
- [ ] 重构已完成符号调用点和死代码扫描
- [ ] 预设规范未在接入仓手工定制
- [ ] P0 已修复，P1 已提供证据并获得确认
- [ ] 新增技术债已说明原因和后续处理方式
