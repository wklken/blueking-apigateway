## 4. 调用规范

- 输入和输出优先使用结构化数据；错误必须包含可执行的修复信息。
- 只读探测优先于写操作；外部状态写入需要单独授权。
- 网络调用设置超时；仅对明确可重试且幂等的操作使用有限重试。
- 命令从组件规定目录执行，先运行最小范围验证，再运行组件门禁。
- Skill、MCP、CLI 和配置的权威清单变更应先更新治理源，再重新生成本文件。

## 5. 敏感操作

| 操作 | 要求 |
|------|------|
| 删除或覆盖用户文件 | 先确认范围；仅清理由当前任务产生的文件 |
| 数据库迁移 | 需要明确授权、迁移和回滚方案 |
| 生产数据库/etcd/TAPD 写入 | 需要明确目标、凭据和写入授权 |
| commit | 用户明确授权后执行 |
| push | 用户明确授权后执行 |
| PR/评论/发布 | 用户明确授权后执行，提交前复核 diff 和验证证据 |
| 密钥、Token、Cookie、DSN | 不写入代码、日志、文档或 PR |

## 6. 稳定性和降级

- 外部工具不可用时明确报告，不伪造结果。
- graphify 缺失时不生成空图谱或伪造 `graph.json`。
- 组件运行时不正确时先恢复环境，再判断代码失败。
- 验证因凭据或外部服务阻塞时，记录精确命令、阻塞原因和未覆盖范围。
